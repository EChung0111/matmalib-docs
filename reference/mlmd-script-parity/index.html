    AIMNet script integration¶

    The mlmd interface incorporates the active simulation workflows from run_md_aimnet2.py, build_solvated_cell.py, and analyze_metadynamics.py in the AIMNet project. The table maps script settings and behavior to the library API. Configurations are nested dataclasses, for example mlmd.MDConfig(...).

    Script feature Library interface

    Default 2025 model ensemble mlmd() uses all four AIMNet2-2025 B97-3c/D3 members
    Input geometry, charge, multiplicity, PBC, cell, minimum-distance check XYZ/PDB path, State, or ASE Atoms; SystemConfig fields

    Library additions and deliberate differences¶

    The library adds NVE, additional NVT thermostats, isotropic NPT integrators, State inputs/outputs, explicit output protection, and atomic restart checkpoints every 1,000 steps and at completion. Every MD run saves positions, velocities, RNG state, thermostat/barostat state and constraints, including ordinary MD and any custom PLUMED input. Generated metadynamics also saves its bias history.

    Library defaults do not encode the original experiment's atom numbers, box, density, two-million-step duration, or fine-tuned fifth ensemble member. Set the configs explicitly to reproduce that experiment. The old velocity-cap code was commented out; the library offers an optional velocity abort guard instead. Older nested script copies' retry-and-continue minimization behavior is replaced by an explicit convergence result and failure by default.

    For fixed-cell periodic distance CVs, normalized metadynamics weights and an automatic grid are enabled by default. For other CVs and NPT, supply suitable explicit grid bounds to enable normalization, or reconstruct the FES from HILLS. Ordinary MD and generated PLUMED input support automatic restart. Custom PLUMED input still produces checkpoints, but restoring its bias requires action-specific restart files. The 1D analysis retains the source script's limitations on multidimensional and periodic-boundary-crossing free-energy profiles.

    Script-only process management (package installation, Python re-execution, hardcoded cluster library paths, global compilation environment changes and CLI/IDE globals) is replaced by optional package dependencies and explicit API arguments. Select a timestamped output_dir in Python when needed. Training, dataset conversion, model export, and training TUI utilities are outside this simulation interface.

    See the README simulation guide for installation, examples, units and restart requirements.
